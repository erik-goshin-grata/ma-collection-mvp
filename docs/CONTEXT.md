## 1. Pipeline (14 stages + funding branch)

| # | Stage module | Role |
|---|---|---|
| 1 | `scrape_pr_newswire` | Discover/scrape source → `source_raw` (alt ingests: `adapters/csv_url.py`, `scripts/ingest_predictleads.py`) |
| 2 | `relevancy_filter` | Binary in-scope gate (Haiku). Sets `source_status` RELEVANT / NOT_RELEVANT |
| 3 | `deal_type_classify` | Classify `v2_event_type`, target status, dates (Sonnet). Sets `status=CLASSIFIED` |
| 4 | `high_confidence_extract` | M&A extraction (Sonnet) → `HC_EXTRACTED`. **Excludes funding event types** (they go to 4b) |
| 4b | `funding_hc_extract` | **Funding extraction** (VC_ROUND/GROWTH_EQUITY/VENTURE_DEBT) → round + investor fields → `HC_EXTRACTED` |
| 5 | `sec_trigger_detect` | Flags US-public deals for SEC enrich (no-op on WEB_URL rows) |
| 6 | `sec_enrich` | SEC EDGAR enrichment |
| 7 | `low_confidence_extract` | Second-pass fields (advisors, components) → `LC_EXTRACTED` |
| 8 | `entity_cluster` | Cluster same-deal rows → `CLUSTERED`. **Requires target_name + acquirer_name** (see bug #5) |
| 9 | `aggregate` | Merge cluster → `transaction_record`, rows → `AGGREGATED`. Derives equity/implied-equity/EV |
| 10 | `sec_documents` | Expanded SEC filing fetch |
| 11 | `agreement_extract` | Merger-agreement extraction |
| 12 | `summarize` | Deal summary (Sonnet) |
| 13 | `rationale_tag` | Strategic rationale (Opus) |
| 14 | `export` | `exports/transactions_<run_id>.csv` |

**status flow:** `FETCHED → RELEVANT → CLASSIFIED → HC_EXTRACTED → LC_EXTRACTED → CLUSTERED → AGGREGATED`

**Run modes** (`run.py --mode=`): `resume` (default; stages 2→14, SEC no-ops on WEB_URL), `full`, `scrape`, `extract` (2–6+4b), `aggregate` (8–9), `sec-documents`, `agreement-extract`/`-rerun`, `generate` (12–13), `export`, `rerun-prompt --prompt --version`. DB path via `DB_PATH` env (default `data/ma_mvp.db`).

**Model tiers** (config defaults; wired 2026-08-03): Opus `claude-opus-4-7`, Sonnet `claude-sonnet-4-6`, Haiku `claude-haiku-4-5`. relevancy=Haiku; classify/HC/funding-HC/summary=**Sonnet**; rationale=Opus.

## 3. Schema

Tables: `source_raw` → `staging_extraction` (+ `staging_investor`) → `transaction_record`.
Migrations: `001_initial.sql`, `002_v2_prompt_alignment.sql` (V2 columns: `v2_event_type`,
`event_history_type`, `recap_type`, `*_type_v2`, `financials_disclosure_status`),

`staging_investor` table). Applied automatically in `db._apply_migrations` (as of 2026-08-04).

**Important:** the V2/funding columns are plain `TEXT` with **no CHECK constraints** — the
schema does *not* enforce enums. The enum contract lives entirely in the **prompt** (what the
model is told) and the **stage validators** (`_VALID_*` frozensets). That split is where drift
hides — see §4.

### ⚠️ Relevancy reason-code drift (the live one)
The prompt (`relevancy_filter.md` 0.5) declares these RELEVANT-side codes that the **stage
does not recognize**:
- **`VC_ROUND_OR_FUNDING`** — not in `_VALID_REASON_CODES`, not in `_REASON_CODE_ALIASES` → normalized to `AMBIGUOUS_BUT_LIKELY_DEAL`. *(Observed live: funding rows land as AMBIGUOUS, erasing the funding signal at the relevancy layer.)*
- **`RECAPITALIZATION`** — same: falls through to `AMBIGUOUS_BUT_LIKELY_DEAL`.
- **`ASSET_PURCHASE`** — the prompt uses it; the stage handles it via alias → `ACQUISITION_ANNOUNCEMENT` ✅ (this one is covered; see the older asset-purchase note).

Rows are still kept RELEVANT (the normalizer never drops a correctly-classified row), but the
funding/recap reason label is lost. **Fix:** add `VC_ROUND_OR_FUNDING` and `RECAPITALIZATION`
to `_VALID_REASON_CODES` (and/or aliases) so the stage matches prompt 0.5.

## 5. Funding path specifics (the new surface)

- Relevancy keeps funding in scope: VC rounds (Seed→Series N, angel, crowdfunding), minority/growth equity, recaps, venture debt.
- Classifier routes funding to `VC_ROUND` / `GROWTH_EQUITY` / `VENTURE_DEBT`; stage 4 **excludes** these so **stage 4b** extracts them (round label/size, pre/post-money, investors → `staging_investor`).
- **Two bugs currently block funding end-to-end** — see #5 and #6.

## 6. Known bugs & gaps

1. `run.py` stage-alias typo — fixed (PR #1).
2. V2 migrations not auto-applied — fixed (2026-08-04).
3. Stage code not synced to V2 prompt `.format()` placeholders — fixed (PR #1).
4. Relevancy short-code drop (`ACQUISITION` etc.) — mitigated by `_REASON_CODE_ALIASES`.
5. **`entity_cluster` requires `acquirer_name`** → VC_ROUND/VENTURE_DEBT (no acquirer) strand at `LC_EXTRACTED`, never export. Fix: funding branch clusters on `target_name` alone. **Reviewed — approved w/ 4 fixes** (use `round_size` not `value_amount`; soft/precision-safe dates; widen SELECT; gate on both-funding). Spec: `handoff_bug5_funding_clustering.md`; review: `review_bug5_feedback.md`.
6. **`funding_hc_extract` multi-transaction INSERT** supplied 36 params to a 34-col INSERT (reused `round_params`) → crash on any source with ≥2 funding events. **Fixed locally 2026-08-06** (explicit 34-tuple); UPDATE branch still lists `valuation_currency` twice (harmless smell). **Verify + commit.** Patch: `handoff_bug6_patch.md`.
7. **Relevancy reason-code drift** (§4): prompt 0.5 emits `VC_ROUND_OR_FUNDING`/`RECAPITALIZATION`; stage squashes to `AMBIGUOUS_BUT_LIKELY_DEAL`. **Reviewed — converged** (add both codes; keep `classification` param; add a prompt-declared demarcated enum block + parity test). Spec: `handoff_bug7_relevancy_reason_codes.md`; review: `review_bug7_feedback.md`.
8. **Funding value semantics:** a growth/minority raise (e.g. 10x Banking $53.7M) routed to `MINORITY_INVESTMENT` recorded the *check size* as `equity_value`/`implied_equity_value`. **Reviewed — approved w/ corrections** (post/pre-money already exist in schema but M&A HC prompt must extract them; `investment_amount` needs a migration; reuse existing `_FUNDING_EVENT_TYPES`; avoid double pct gross-up; KG is *not* "unchanged" — it becomes `implied≈$750M`). Spec: `handoff_bug8_funding_value_semantics.md`; review: `review_bug8_feedback.md`.
9. **[DECISION — resolved] VC_ROUND vs GROWTH_EQUITY boundary.** Keep the automated rule (investor-archetype + profitability, "when unclear → VC_ROUND"), optionally a *narrow* tie-break nudge; **Base Power stays VC_ROUND**. Marquee-deal edge cases handled by a **researcher override in the research tool** — a separate layer, **not built yet**, deferred. Reclassifying VC_ROUND↔GROWTH_EQUITY is label-only (same downstream path), so it's safe to punt to a human. Forward note: when the research tool writes overrides, the pipeline must preserve them across re-run (clone the `net_debt` pattern; a general per-field override table).
